# Release Testing Standards

These standards govern how [[container-release-cli]] and
[[module-release-core]] are tested. They adopt the Spec CLI's testing
standard by reference and state only what this repository binds.

**Adopted:** [Testing Standards for the Spec CLI](https://github.com/brettcallaghan/specs/blob/3e612b9/specs/standards/testing-standards.md),
pinned to commit `3e612b9`. Its requirements apply here as written: unit
tests for components, snapshot cases for observable behavior, and every case
citing the acceptance criterion it verifies. They are not copied, so a
later revision of the upstream document binds this repository only when the
pin is moved.

Each binding carries a stable identifier. An identifier is never renumbered
once assigned, and a retired one is never reused.

---

## Snapshot Cases

**TST-001:** Each snapshot case SHALL be a directory
`testdata/cases/<case>/` holding `case.toml`, an optional `input/` and an
`expected/` directory.

**Rationale:** the layout is data, so the cases replay under any harness.

---

**TST-002:** The `cites` property of every `case.toml` SHALL list what the
case verifies, each entry being an acceptance-criterion id or a
`slug#anchor` for a contract section.

**Rationale:** a case has no code to carry a citation comment, and a
criterion with no case must be findable.

---

## Regeneration

**TST-003:** Expected artifacts and golden help SHALL be regenerated by
`scripts/regenerate-snapshots.sh` and SHALL NOT be edited by hand.

**Rationale:** a hand-edited snapshot records what the author expected, not
what the implementation does, and the replay can no longer disagree with it.

---

**TST-004:** A change that regenerates snapshots SHALL have the resulting
diff reviewed before it is committed.

**Rationale:** the script does not judge the diff, and a changed snapshot
is a changed command surface.

---

## Golden Help

**TST-005:** The files under `testdata/help/`, one per command, SHALL be
the normative help text of [[contract-release-cli]].

**Rationale:** the contract names the golden files as the surface, so the
implementation is checked against them and not the reverse.

---

## Coverage

**TST-006:** Coverage figures SHALL be committed in `README.md` by
`scripts/coverage.sh`, and a change to Go code SHALL commit that script's
diff with it.

**Rationale:** CI's coverage job fails on stale figures. The figures depend
on the Go version in `go.mod`, so another toolchain moves the counts.
